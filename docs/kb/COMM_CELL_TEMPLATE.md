# Knowledge / Comm Cell template

## KB-SS-XXX - Short descriptive title

**Status:** Open | Monitoring | Workaround | Resolved | Rejected | Standard  
**Last reviewed:** YYYY-MM-DD  
**Environment:** device / OS / source baseline / relevant dependency versions

### Context
What work was being attempted and why?

### Symptom / observation
What was actually observed? Keep direct observation separate from inference.

### Impact
What does this block, degrade or put at risk?

### Root cause
State only what is proven. If unknown, say `Unknown` and list the leading hypotheses separately.

### Resolution / decision
What changed, or what architectural decision was taken?

### Workaround
If the issue remains open, what safe temporary path exists?

### Validation
How was the resolution tested? Separate machine gates from manual device/visual/audio QA.

### Reusable lesson / standard
What should future ports or future contributors do differently because of this result?

### Related records
Source files, commits, issues, experiments, rejected approaches and external references.
